Use `defaultExpandedKeys` for the initial uncontrolled state. Use `expandedKeys` with `onExpandedChange` to control which items are open. The expanded keys correspond to each `AccordionItem` `id`.

### AccordionItem

| Name                         | Type                            | Default   | Description                                       |
| ---------------------------- | ------------------------------- | --------- | ------------------------------------------------- |
| `id`                         | `Key`                           | —         | Identifier that matches `expandedKeys`.           |
| `defaultExpanded`            | `boolean`                       | `false`   | Whether the item is initially expanded.           |

### AccordionItemHeader and AccordionItemTitle

`AccordionItemHeader` accepts the header content. `AccordionItemTitle` renders the item heading and accepts `level`, which defaults to `3`. Both also support `id`, `UNSAFE_className`, and `UNSAFE_style`.

### AccordionItemPanel

`AccordionItemPanel` contains the expandable content. It supports standard accessibility labels and `role`, which defaults to `group`; use `region` when the panel needs a landmark role.

## TableView, ListView, and TreeView

ActionBar is intended to be rendered by collection components through `renderActionBar`. Pass the selected collection size to `selectedItemCount` and keep the actions inside the bar. The same pattern works with `ListView` and `TreeView`.

<Source language="tsx" code={`<TableView
  aria-label="Table with action bar"
  selectionMode="multiple"
  renderActionBar={(selectedKeys) => (
    <ActionBar selectedItemCount={selectedKeys.size}>
      <ActionButton aria-label="Edit">Edit</ActionButton>
      <ActionButton aria-label="Copy">Copy</ActionButton>
      <ActionButton aria-label="Delete">Delete</ActionButton>
    </ActionBar>
  )}
>`} />

## Clearing selection

Use `onClearSelection` to connect the built-in clear-selection button to the state owned by the collection.

<Source language="tsx" code={`<ActionBar

>
  <ActionButton aria-label="Archive">Archive</ActionButton>

## Pending

Set `isPending` to display an indeterminate spinner. Pending buttons remain focusable but do not accept press or hover interactions while pending.

<Source language="tsx" code={`import { useState } from "react";
import { ActionButton } from "@/components/spectrum/ActionButton";

function PendingButton() {
  const [isPending, setPending] = useState(false);

  return (
    <ActionButton
      isPending={isPending}
      onPress={() => {
        setPending(true);
        setTimeout(() => setPending(false), 5000);
      }}>
      Save
    </ActionButton>
  );
}`} />

- `isQuiet` applies the quiet ActionButton style.
- `isDisabled` disables the button.

- `staticColor` supports `auto`, `black`, and `white` when the button appears over a colored background.
- Use `type="submit"` or `type="reset"` when the button participates in a form.

# SideNav

A SideNav provides users with a way to navigate a nested hierarchical set of links. It supports static and dynamic collections, expansion, routing, sections, disabled items, and accessible navigation semantics.

## Basic usage

```tsx
import {SideNav, SideNavItem, SideNavItemContent, SideNavItemLink, Text} from "@/components/spectrum/SideNav";

<SideNav aria-label="Files" selectedRoute="/guidelines" defaultExpandedKeys={["guidelines"]}>
  <SideNavItem href="/guidelines" id="guidelines" textValue="Guidelines">
    <SideNavItemContent>
      <SideNavItemLink><Text>Guidelines</Text></SideNavItemLink>
    </SideNavItemContent>
  </SideNavItem>
</SideNav>
```

<Canvas of={SideNavStories.Default} />

## Sections

Use `SideNavSection` and `SideNavHeader` to group related items. Sections are non-collapsible and non-interactive.

<Canvas of={SideNavStories.WithSections} />

## Routing and selection

SideNav does not support uncontrolled selection. Manage the current route through `selectedRoute` and update it from your router. Items with an `href` must render a `SideNavItemLink` inside `SideNavItemContent`.

## Collections and nesting

SideNav follows the Collection Components API. Use `items` and a recursive render function for dynamic collections, or use static nested `SideNavItem` children for small trees. Set `defaultExpandedKeys` for initial expansion and `expandedKeys` with `onExpandedChange` for controlled expansion.

## Accessibility

Provide `aria-label` or `aria-labelledby` for the navigation landmark. Give each item a useful `textValue` for typeahead and accessible collection behavior. Use `disabledKeys` for items that cannot be selected or interacted with.
